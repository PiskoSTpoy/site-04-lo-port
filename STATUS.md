# STATUS — ретрофит под seo-2026-playbook

## kran-lo.ru — этап 1 (шелл/шаблон), 25.09.2026

**Контекст:** Eleventy/11ty, полностью статический сайт без клиентского фреймворка — класса регрессии «hydration mismatch» (пойманного на manipmo.ru и kranneva.ru) здесь в принципе не существует, любая вставка узла в HTML безопасна с точки зрения гидратации.

**Важная находка ДО патча:** этот сайт уже прошёл через собственный, более ранний проход по похожим правилам («Волна 11/14/16» в комментариях кода) — но только для 15 статей блога (`_includes/blog-article.njk`): там уже есть `id` на H2 (через фильтры `extractH2s`/`injectH2Ids` в `eleventy.config.js`), desktop- и mobile-TOC (`.toc--desktop`/`.toc--mobile`, серверный рендер, не клиентский JS), ролевой byline «Логистическая служба КРАН-ЛО», FAQ-блок, `sources.njk`, related-posts. Остальные ~51 страница (park/uslugi/marshruty/keysy/kalendar/documents/kontakty) используют `layout.njk` НАПРЯМУЮ, минуя эту обвязку — там не было НИЧЕГО из перечисленного.

**Baseline:** 66 стр., 3 FAIL, 63 WARN, 0 PASS. Топ: нет источников (66), нет `<time>` (65), нет автора (63), короткий intro (57), сущность не названа (54), нет TOC (50), первое предложение не тезис (45), нет FAQ (35), HN без id (30).

**Сделано:** вместо нового postbuild-скрипта (как на предыдущих 3 сайтах) — переиспользован уже существующий в проекте фильтр `injectH2Ids` (он идемпотентен: пропускает `<h2>`, где id уже стоит), просто добавлен ещё раз в `_includes/layout.njk` вокруг `{{ content | safe }}`. Теперь id получают H2 на ВСЕХ типах страниц, не только в блоге, без создания нового файла и без дублирования логики. После патча «HN без id» пропало из топ-10 предупреждений полностью.

**Сознательно НЕ сделано в этом проходе:**
- TOC для не-блоговых страниц. `.toc--desktop`/`.toc--mobile` жёстко завязаны на grid-раскладку `.article-shell` (см. `main.css`), которой у park/uslugi/marshruty/keysy нет — у каждого типа страницы своя вёрстка (карточки, таблицы сравнения и т.д.). Перенос TOC туда без per-шаблонного анализа рискует сломать сетку; это не regex-патч, а отдельная работа по каждому типу страницы.
- Byline/автор, sources, FAQ — на этих же ~51 страницах, по той же причине (нет общей обвязки, конкретные тексты/факты нужны для честной подписи и списка источников).
- Контент-уровень (сущность «KRAN-LO» в абзацах, тезис первым предложением, длина intro) — как и на предыдущих 4 сайтах, отдельный будущий проход.

**Живая проверка:** `/park/kb-403b/` — H2 с id на месте (`id="откуда-эта-машина-и-почему-она-до-сих-пор-в-строю"` — сайт использует кириллические слаги через собственный `slugify()`, сохранено как есть, не переведено в транслит, чтобы не расходиться с уже существующей практикой блога), консоль чистая, 375px — без горизонтального скролла. `/keysy/dostavka-v-mezhsezone/` — H2 на странице нет вовсе (не ошибка патча, у страницы такая структура).
